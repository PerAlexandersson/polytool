# exact-algebra

Exact integer and rational arithmetic kernels, with generic sparse polynomial adapters.
The crate requires Rust 1.82 and depends only on the `num-*` crates.
It is available in-tree and is not currently published to crates.io.

| Module | Purpose |
| --- | --- |
| `groebner` | Generic sparse division, Lex/GrLex/GrevLex orders, Buchberger with product/chain criteria and batched reducer rows; owned rational polynomials and borrowed consumer term maps |
| `primes` | Deterministic word-size primality validation and descending prime streams |
| `modular_arithmetic` | Overflow-safe word-size residue operations |
| `chinese_remainder` | Batched BigInt CRT with signed, squared-Hadamard and nonnegative bounds |
| `rational_reconstruction` | Bounded BigInt rational reconstruction with congruence and uniqueness checks |
| `denominators` | Row-wise denominator clearing and positive row scales |
| `integer_elimination` | Internal fraction-free engine; optional `test-hooks` fallback guard |
| `linear_systems` | Exact solves, fraction-free inverse, rank/nullity and certified rational kernels |
| `sparse_modular` | Sparse consistency, rank and solution with selectable fill-reducing row orders |
| `multimodular` | Two-profile agreement, bounded CRT and independent spare-prime verification |
| `nonnegative_matrix_product` | Division-free products with inclusive column bounds, nonnegative CRT and an unused verification prime |
| `dense_modular` | Prime-field row reduction and CRT reconstruction of leading principal minors |

Matrices are row-major `Vec<Vec<_>>`; kernel basis vectors are stored separately.
All indices are zero-based. Reconstruction requires a justified bound on the true
integer or rational target; a modulus threshold alone cannot validate modular input.
Higher-level quotient adapters remain separate consumers.

```rust
use exact_algebra::chinese_remainder::ChineseRemainderAccumulator;
use exact_algebra::primes::ValidatedPrime;

let mut reconstruction = ChineseRemainderAccumulator::new(1);
reconstruction.combine_prime(&[3], ValidatedPrime::new(5)?)?;
reconstruction.combine_prime(&[5], ValidatedPrime::new(7)?)?;
assert_eq!(reconstruction.reconstruct_symmetric(&[2.into()])?, vec![num_bigint::BigInt::from(-2)]);
# Ok::<(), Box<dyn std::error::Error>>(())
```

The optional `test-hooks` feature exposes a thread-local `ForcedFallback` guard
for exercising rational fallback paths. It is absent from normal builds.

The checked `examples/sparse_consistency.rs` constructs and solves a sparse system.

The checked `examples/nonnegative_matrix_product.rs` multiplies signed inputs
with proved nonnegative output bounds. Bounds must be mathematical upper bounds;
modular agreement alone does not supply them.

The checked `examples/groebner.rs` reduces the ideal generated by `x` and
`x+y` to `[x,y]`. `groebner::SparsePolynomial` and the coefficient providers
allow a consumer to use its existing sparse representation without copying
maps into a second polynomial type. Legacy consumer paths may re-export the
order and option types and wrap the generic computation results.

The rational entry point
`groebner::reduced_lexicographic_groebner_basis_with_budget` uses ordered input
reduction, minimal degree/lex-lcm pair scheduling and tail interreduction in
insertion order. `GroebnerBudget` shares subtraction steps across calls and
checks coefficient bits after each debit; the basis-size check applies only
after appending an S-pair remainder. Exhaustion returns typed `GroebnerError`
variants. The checked `examples/bounded_groebner.rs` demonstrates the exact
last-step boundary. Other Gröbner entry points remain unbounded. Use only small systems;
coefficient providers must satisfy the exact field laws and bounded rational
coefficient types can still overflow. Finite-prime agreement alone does not
certify a rational ideal.

`groebner::certified_modular_groebner_basis` groups word-prime computations by
ordered leading profile, requires two matching profiles, aligns supports by
union for arbitrary-precision CRT and rational reconstruction, and verifies
the full result at a distinct unused prime. It then checks every rational
S-pair and both ideal containments. `check_rational_groebner_basis` replays
these exact checks independently of the modular evidence; `[1]` fails for a
proper input ideal. Reverse containment currently recomputes a rational basis,
so certification may cost more than solving directly. A caller-supplied finite
prime list bounds retries; each individual basis computation remains unbounded.
The checked `examples/certified_modular_groebner.rs` demonstrates vanishing
support at one reconstruction prime. Legacy fixed-width consumer pair lifts
remain uncertified and retain their support/error contracts.
